<summary>Задание</summary>

_Для хранения данных о клиентах, продуктах, заявках и транзакциях требуется реляционная база данных._

**Задача:**

Спроектировать оптимальную схему базы данных микрофинансовой организации.

**Требования:**

* Проектирование схемы
  * Разработайте нормализованную схему базы данных для основных сущностей: клиенты, продукты, заявки, транзакции
  * Определите типы связей между таблицами
  * Создайте DDL-скрипты с указанием типов данных, ограничений и индексов
* Ограничения целостности
  * Добавьте первичные и внешние ключи для обеспечения ссылочной целостности
  * Добавьте `CHECK`-ограничения для валидации бизнес-правил
  * Настройте каскадные операции для связанных данных
* Оптимизация производительности
  * Создайте индексы для часто используемых полей поиска и сортировки:
    * Быстрый поиск клиента по телефону и по серии + номеру паспорта
    * Поиск всех активных продуктов
    * Фильтрация заявок по статусу и дате создания
    * Аналитика по месяцам и годам
    * Часто выполняемые JOIN-ы между заявками и транзакциями
  * Для каждого индекса обоснуйте, почему выбран именно он
* CRUD-запросы
  * Напишите SQL-запросы:
    * Добавить нового клиента
    * Обновить телефон клиента по `id`
    * Деактивировать кредитный продукт (`is_active = false`)
    * Удалить клиента (с учётом существующих заявок)
    * Вывести все активные заявки клиента по его телефону
    * Вывести историю транзакций по конкретной заявке
    * `CREATE`, `READ`, `UPDATE`, `DELETE` для каждой таблицы
  * Аналитические запросы:
    * Топ-10 клиентов по выданной сумме за всё время (ФИО + сумма).
    * Топ-10 клиентов за текущий год с указанием роста/падения относительно прошлого года в %.
    * Анализ продуктовой линейки: для каждого активного продукта вывести
      * название, мин/макс сумма, годовая ставка в %
      * количество поданных заявок
      * количество выданных
      * процент одобрения
      * общая выданная сумма
    * Сезонность: количество поданных и выданных заявок по месяцам за последние 36 месяцев (с названием месяца и года).
    * Матрица одобрения по возрасту клиентов:
      * возрастные группы 18–25, 26–35, 36–50, 51+
      * % одобренных заявок в каждой группе
    * Найти «токсичных» клиентов:
      * клиенты, у которых ≥ 3 заявки за последние 6 месяцев
      * и при этом процент одобрения < 30%
      * вывести ФИО, телефон, кол-во заявок, кол-во одобрений и % одобрения.
  * Как понять, когда для аналитических запросов нужно добавлять индексы? Почему нельзя просто покрыть все поля всеми индексами?<br>
