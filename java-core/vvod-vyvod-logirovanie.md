# Ввод, вывод, логирование

## `System.out`, `System.err` и `System.in`

> **Поток ввода-вывода** — это канал, через который программа получает или передаёт данные.

Здесь слово "поток" не означает поток как в многопоточности — речь не о параллельном выполнении кода, а о передаче данных.

У класса `System` есть три стандартных потока:

<table><thead><tr><th width="179.921875"></th><th>Назначение</th><th>Тип</th></tr></thead><tbody><tr><td><code>System.out</code></td><td>Обычный вывод программы</td><td><code>PrintStream</code></td></tr><tr><td><code>System.err</code></td><td>Вывод сообщений об ошибках и другой диагностической информации</td><td><code>PrintStream</code></td></tr><tr><td><code>System.in</code></td><td>Получение входных данных</td><td><code>InputStream</code></td></tr></tbody></table>

При обычном запуске в консоли `out` и `err` выводят текст в неё, а `in` позволяет получать ввод с клавиатуры. Но это не обязательно всегда так: например, вывод можно направить в файл, а входные данные — прочитать из файла вместо клавиатуры.

***

В выражении:

```java
System.out.println("Hello");
```

* `System` — класс.
* `out` — его **статическое поле**, в котором хранится ссылка на объект `PrintStream`.
* `println()` — метод этого объекта.

То есть сначала обращаемся к полю `System.out`, а затем вызываем метод у полученного объекта.

***

### `System.out`

Через `System.out` можно вывести результат работы программы:

```java
System.out.println("Заказ №15 создан");
System.out.println("Стоимость доставки: 249 руб.");
```

Метод `println()` добавляет перевод на новую строку. Если он не нужен, используется `print()`:

```java
System.out.print("Заказ ");
System.out.print("создан");
```

Результат:

```
Заказ создан
```

Оба метода умеют выводить не только строки, но и другие значения, например числа и `boolean`.

***

### `System.err` — вывод ошибок

Например:

```java
System.err.println("Не удалось создать заказ");
```

У `System.err` тот же тип `PrintStream`, поэтому у него есть методы `print()`, `println()` и `printf()`.

Отличие от `System.out` — прежде всего **назначение и возможность отдельно направлять вывод**. Это два разных канала, даже если в консоли их сообщения показываются рядом.

Представим, что программа формирует отчёт. Сам отчёт нужен в одном файле, а сообщения о проблемах — в другом.

При запуске через Bash можно написать:

```bash
java Main > result.txt 2> errors.txt
```

Вывод `System.out` попадёт в `result.txt`, а `System.err` — в `errors.txt`.

Сам вызов `System.err.println()` **только выводит сообщение**. Он не кидает исключение и не завершает программу. Если после обнаружения ошибки нужно прекратить выполнение метода или выбросить исключение, это нужно написать отдельно.

***

> **Буфер** — временное место в памяти, где данные могут накапливаться перед дальнейшей передачей.

Буферизация позволяет вместо того, чтобы выполнять отдельную операцию для каждого фрагмента данных, накапливать их, и выполнять операцию для группы. А **сброс буфера**, или `flush`, передаёт накопленные данные дальше.

В OpenJDK 21 **и `System.out`, и `System.err` создаются с буферизацией и включённым автоматическим сбросом**. Например, вызов `println()` приводит к автоматическому сбросу буфера.

При необходимости сброс можно запросить явно:

```java
System.out.flush();
```

***

### `System.in`&#x20;

Через `System.in` программа получает данные извне. Для чтения введённого текста удобно использовать `java.util.Scanner`:

```java
Scanner scanner = new Scanner(System.in);

System.out.print("Введите имя: ");
String name = scanner.nextLine();

System.out.println("Здравствуйте, " + name);
```

Здесь `Scanner` — отдельный объект, которому мы передали источник данных:

```java
new Scanner(System.in)
```

Вызов `nextLine()` читает строку. При вводе с клавиатуры программа может остановиться на этом месте и ждать, пока пользователь введёт текст и нажмёт Enter.

***

## Форматирование текста

Представим, что нужно вывести сообщение с именем пользователя и номером заказа. Можно собрать строку через `+`:

```java
System.out.println("Пользователь " + name + " оформил заказ №" + orderId);
```

Но когда переменных становится много, выражение сложнее читать. А если нужно ещё и вывести число с определённым количеством знаков после запятой, одной конкатенации недостаточно.

Для таких задач используют **форматирование**: задают шаблон и подставляют в него значения.

***

### `System.out.printf()` — форматировать и сразу вывести

```java
System.out.printf("Пользователь %s оформил заказ №%d%n", "Anna", 15L);
```

Результат:

```
Пользователь Anna оформил заказ №15
```

Первый аргумент — **строка формата**, то есть шаблон. В нём находятся специальные обозначения:

<table><thead><tr><th width="183.9375">Обозначение</th><th>Что означает</th></tr></thead><tbody><tr><td><code>%s</code></td><td>Текст</td></tr><tr><td><code>%d</code></td><td>Целое число</td></tr><tr><td><code>%f</code></td><td>Число с дробной частью</td></tr><tr><td><code>%.2f</code></td><td>Число с двумя знаками после запятой</td></tr><tr><td><code>%n</code></td><td>Перевод на новую строку</td></tr><tr><td><code>%%</code></td><td>Обычный символ <code>%</code></td></tr></tbody></table>

В нашем примере вместо `%s` подставляется `"Anna"`, вместо `%d` — `15L`.

`%n` не требует отдельного аргумента: он означает перевод строки. В отличие от `println()`, метод `printf()` **не добавляет перевод строки автоматически** — его нужно предусмотреть в шаблоне.

***

Тип значения должен подходить к обозначению. Так правильно:

```java
System.out.printf("Заказ №%d%n", 15);
```

А так — нет:

```java
System.out.printf("Заказ №%d%n", "пятнадцать");
```

`%d` ожидает целое число, но получает строку. При выполнении возникнет `IllegalFormatConversionException`.

***

### `String.format()` — форматировать и получить строку

У `String.format()` похожий синтаксис:

```java
String message = String.format("Пользователь %s оформил заказ №%d", "Anna", 15L);
```

Но этот вызов **ничего не выводит в консоль**. Он возвращает готовую строку, которую мы сохраняем в `message`.

Дальше можно использовать её как любую другую строку:

```java
System.out.println(message);
```

Или передать другому методу, например для отправки уведомления.

***

#### Почему число иногда выводится с точкой, а иногда — с запятой?

В разных регионах приняты разные правила записи чисел:

```
249.50
249,50
```

В Java такие настройки представлены классом **`Locale`**. Если `Locale` не указать явно, форматирование использует значение по умолчанию. Поэтому результат может отличаться на разных компьютерах.

Для предсказуемого результата `Locale` можно передать первым аргументом:

```java
String message = String.format(
        Locale.forLanguageTag("ru-RU"),
        "Стоимость доставки: %.2f руб.",
        249.5
);

System.out.println(message);
```

Результат:

```
Стоимость доставки: 249,50 руб.
```

А здесь будет точка:

```java
String price = String.format(Locale.US, "%.2f", 249.5);
// price = "249.50"
```

У `System.out.printf()` тоже есть вариант с явным указанием `Locale`.

***

### `DecimalFormat`

`String.format()` удобен для формирования **целого сообщения**, в которое подставляются разные значения.

`DecimalFormat` предназначен прежде всего для **форматирования чисел**. Ему задают образец того, как должно выглядеть число.

Например:

```java
DecimalFormat format = new DecimalFormat(
        "0.00",
        DecimalFormatSymbols.getInstance(Locale.forLanguageTag("ru-RU"))
);
String result = format.format(249.5);
System.out.println(result); // 249,50
```

Здесь `"0.00"` — шаблон числа.

`DecimalFormatSymbols` задаёт используемые символы, в том числе десятичный разделитель. Поэтому в шаблоне написана точка, но в результате для выбранной локали появляется запятая.

***

* **`0`** — обязательная цифра. Если нужного разряда нет, будет добавлен ноль.
* **`#`** — необязательная цифра. Лишние нули ради неё не добавляются.

Примеры для русских настроек:

| Шаблон | Исходное число | Результат |
| ------ | -------------: | --------- |
| `0.00` |        `249.5` | `249,50`  |
| `0.00` |          `249` | `249,00`  |
| `0.##` |          `249` | `249`     |
| `0.##` |      `249.567` | `249,57`  |
| `0000` |           `15` | `0015`    |

В последнем примере шаблон требует минимум четыре цифры, поэтому перед `15` добавляются два нуля.

В примере с `249.567` количество дробных знаков ограничено двумя, поэтому отображаемое значение округляется.

**Форматирование изменяет представление числа в строке, а не исходное значение переменной.** `DecimalFormat` можно использовать повторно для нескольких чисел.

## Логирование

Представим, что мы добавили в программу:

```java
System.out.println("Начинаем создание заказа");
...
System.out.println("Проверка завершена");
...
System.out.println("Заказ создан");
```

Для одного запуска это удобно. Но теперь через программу проходят тысячи заказов. Как понять, к какому заказу относится сообщение? Когда оно появилось? Какой класс его написал? Это обычное событие или ошибка?

> * **Логирование** — запись событий, происходящих во время работы программы.
> * **Лог** — такая запись или совокупность записей.
> * **Логгер** — объект, через который код сообщает об этих событиях.

Например, при соответствующей настройке запись может выглядеть так:

```
10:15:32 INFO OrderService — Заказ 15 создан
```

Теперь видно время, уровень события, источник и конкретный заказ.

***

### Уровни логирования

Не все события одинаково важны. Информация о каждом промежуточном вычислении может понадобиться при поиске ошибки, но мешать при обычном наблюдении за программой. Поэтому у записей есть **уровень** — отметка, которая показывает характер и важность события.

<table><thead><tr><th width="110.20703125">Уровень</th><th>Для чего используется</th><th>Пример события</th></tr></thead><tbody><tr><td><code>TRACE</code></td><td>Максимально подробные шаги выполнения</td><td>Проверяется одно из нескольких правил расчёта стоимости доставки</td></tr><tr><td><code>DEBUG</code></td><td>Подробности для поиска причин поведения программы</td><td>Выбрана оплата при получении</td></tr><tr><td><code>INFO</code></td><td>Значимые события нормальной работы</td><td>Заказ полностью создан</td></tr><tr><td><code>WARN</code></td><td>Подозрительная ситуация или проблема, для которой ещё есть рабочий обходной путь</td><td>Основная служба доставки недоступна, используется резервная</td></tr><tr><td><code>ERROR</code></td><td>Ошибка, из-за которой операция не выполнилась</td><td>Не удалось сохранить заказ</td></tr></tbody></table>

***

#### Как работает порог логирования?

Допустим, включили уровень логирования **`INFO`**. Будут записываться события `INFO`, `WARN` и `ERROR`. А `DEBUG` и `TRACE` будут пропускаться.

Если установить **`DEBUG`**, добавятся сообщения `DEBUG`, но `TRACE` по-прежнему не будет записываться.

Если установить **`ERROR`**, из рассматриваемых пяти уровней останется только `ERROR`.

То есть настройка `INFO` означает **показывать INFO и более серьёзные события**.

***

#### `ERROR` — не обязательно остановка программы

Например, один заказ не удалось сохранить. Для этой операции это ошибка, но программа может продолжить обработку других заказов.

Кроме того, вызов:

```java
logger.error("Не удалось создать заказ");
```

сам по себе не равен `throw`. Как и вывод через `System.err`, он сообщает о проблеме, но не определяет дальнейшие действия программы.

При выборе уровня полезно ориентироваться на смысл ситуации. Например, ошибка при вводе пустого адреса — нормальная часть работы программы, а вот если не получилось сохранить полностью корректный заказ — это уже серьезный сбой.

***

### SLF4J

**SLF4J** предоставляет API: интерфейсы и методы, которые мы используем в своём коде:

```java
logger.info("Заказ создан");
logger.warn("Доставка задерживается");
logger.error("Не удалось создать заказ");
```

Его часто называют **фасадом логирования**: приложение обращается к общему набору методов (интерфейсу), а фактические действия выполняет конкретная реализация (наследник).

SLF4J сам по себе работать не будет — ему нужна реализация, которая будет реально выполнять методы. Такой реализацией может быть, например, Log4j2 или Logback.

***

### Log4j2

У Log4j2 есть **собственный API** и реализация **Log4j Core**, которая обрабатывает события: применяет настройки, форматирует записи и направляет их в нужные места.

Поэтому возможны оба варианта:

```
Наш код → Log4j API → Log4j Core
```

или:

```
Наш код → SLF4J → связующий модуль → Log4j Core
```

***

### `java.util.logging`

`java.util.logging`, или **JUL**, входит в стандартную библиотеку Java. Его можно использовать без подключения сторонней библиотеки:

```java
Logger logger = Logger.getLogger("OrderService");

logger.info("Заказ создан");
logger.warning("Доставка задерживается");
logger.severe("Не удалось создать заказ");
```

Обратите внимание на названия методов: здесь `warning()`, а не `warn()`, и `severe()`, а не `error()`.

У JUL собственный набор уровней. В нём есть `INFO`, `WARNING`, `SEVERE`, а для более подробной диагностики — `FINE`, `FINER`, `FINEST`.

И собственный синтаксис параметров:

```java
logger.log(Level.INFO, "Заказ {0} создан", 15L);
```

Здесь используется `{0}`, а не `{}`, как в SLF4J.

***

### Пример с SLF4J

```java
import org.slf4j.Logger;
import org.slf4j.LoggerFactory;

public class Main {

    private static final Logger logger = LoggerFactory.getLogger(Main.class);

    public static void main(String[] args) {
        logger.info("Программа запущена");
    }
}
```

`LoggerFactory.getLogger(Main.class)` получает логгер с именем, соответствующим классу `Main`. Это позволяет отличать сообщения из разных файлов проекта.

Поле сделали `static final`: один раз получили ссылку на логгер для класса и затем используем её в его методах. Создавать новый логгер перед каждой записью не нужно.

***

### Параметризованные логи

Представим, что нужно записать имя пользователя, выполнившего login:

```java
String user = "Anna";
logger.info("User {} logged in", user);
```

Текст сообщения:

```
User Anna logged in
```

`{}` — место для подстановки аргумента.

Аргументов может быть несколько:

```java
logger.info(
        "Заказ {} создан пользователем {}",
        orderId,
        userId
);
```

В первое `{}` подставляется `orderId`, во второе — `userId`.

***

#### Почему лучше не собирать сообщение через `+`?

Можно написать:

```java
logger.debug("Заказ " + orderId + " создан пользователем " + userId);
```

Но Java сначала соберёт итоговую строку, а уже затем вызовет `debug()`. Получается, строка будет сформирована **даже тогда, когда уровень `DEBUG` отключён** и сообщение не будет записано.

Лучше передать шаблон и значения отдельно:

```java
logger.debug(
        "Заказ {} создан пользователем {}",
        orderId,
        userId
);
```

Тогда библиотека сразу увидит, что уровень `DEBUG` сейчас выключен, и не будет тратить ресурсы на формирование строки.

Но оптимизировать так можно только конкатенацию строки — если в качестве параметра передается не просто готовая переменная типа `orderId`, а результат работы какого-то метода, этот метод **в любом случае выполнится**.

Например:

```java
logger.debug("Отчёт: {}", createReport());
```

Предположим, `createReport()` выполняет сложные, долгие вычисления. Этот метод всё равно будет вызван **до `debug()`**, потому что сначала Java должна получить значения аргументов. Наличие `{}` не поможет отключить `createReport()`.

Исправление — явно проверить уровень:

```java
if (logger.isDebugEnabled()) {
    logger.debug("Отчёт: {}", createReport());
}
```

Теперь при выключенном `DEBUG` метод `createReport()` не вызовется.

Для простых переменных такая проверка перед каждой записью не нужна — достаточно параметризованного сообщения.

***

### Как логировать исключения

Представим, что мы уже находимся в блоке `catch`, где `e` — пойманное исключение. Не стоит ограничиваться только:

```java
logger.error("Не удалось сохранить заказ: " + e.getMessage());
```

Так мы передаём лишь текст сообщения исключения и теряем важные подробности о том, **где оно возникло**. Лучше передать в конце сам объект исключения:

```java
logger.error("Не удалось сохранить заказ {}", orderId, e);
```

Здесь `orderId` подставляется вместо `{}`, а `e` передаётся **последним дополнительным аргументом**. Для него не нужно добавлять ещё одно `{}`.

Тогда система логирования получает не только сообщение, но и само исключение, включая **stack trace — список вызовов методов, связанный с местом возникновения ошибки**. Это помогает найти причину сбоя.

***

### Что писать в логах?

Сообщение должно помогать разобраться в событии. Например:

```java
logger.info("Готово");
```

По такой записи сложно понять, **что именно** завершилось. Полезнее:

```java
logger.info(
        "Заказ {} создан, выбрана ли экспресс-доставка: {}",
        orderId,
        expressDelivery
);
```

При этом не нужно записывать все доступные данные. **Пароли, секретные токены и полные платёжные реквизиты не должны попадать в логи.** Также вместо вывода целого объекта часто достаточно его идентификатора:

```java
logger.info("Пользователь {} вошёл в систему", userId);
```

### Уровень логирования и поток вывода — разные вещи

`INFO` и `ERROR` описывают **характер события**. `System.out` и `System.err` определяют **канал, в который передаются данные**.

Поэтому неверно считать, что `logger.info()` обязательно пишет в `System.out`, а `logger.error()` — обязательно в `System.err`.

Например, `slf4j-simple` по умолчанию направляет свои записи в `System.err`, включая `INFO`. В другой конфигурации события разных уровней могут попадать в один файл или обрабатываться по разным правилам. Это задача реализации и её настроек.
