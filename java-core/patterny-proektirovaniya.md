# Паттерны проектирования

При написании кода часто возникают **похожие проблемы**. Например, в конструктор передается много значений:

```java
Order order = new Order(15L, "ул. Лесная, 10", null, false, true);
```

Что означают `false` и `true`? Какой из этих флагов отвечает за оплату при получении, а какой — за экспресс-доставку? Чтобы разобраться, придётся открыть конструктор. А если случайно поменять эти значения местами, компилятор не подсветит ошибку — проблему обнаружим только в процессе выполнения программы.

Один из способов решить эту проблему — сделать отдельный объект, через который можно понятно указать настройки будущего заказа, а затем создать сам заказ:

```java
Order order = Order.builder(15L, "ул. Лесная, 10")
        .payOnDelivery(false)
        .expressDelivery(true)
        .build();
```

Теперь по названиям методов понятно, какие поля какими значениями заполняются. Такой способ можно использовать не только для заказа, но и для других объектов с большим количеством настроек. У него есть название — **Builder**. Это один из паттернов проектирования.

> **Паттерн проектирования** — это способ написать код для решения часто встречающейся проблемы. Он подсказывает, какие классы и методы можно сделать и как использовать их вместе.

Паттерн — это **идея** решения. В одном приложении Builder будет помогать создавать заказы, в другом — настраивать отправку писем. Классы и методы будут разными, но идея останется той же: сначала собрать настройки, затем получить готовый объект.

Паттерны помогают не придумывать решение с нуля каждый раз. Но применять их нужно тогда, когда они действительно помогают. Например, для простого вызова:

```java
User user = new User("Anna", 20);
```

дополнительный Builder будет лишним — код и так понятен без него.
